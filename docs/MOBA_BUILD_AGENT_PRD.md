# 局内出装助手（MOBA Build Agent）产品需求文档（PRD）

版本：v1.0（2026-09-07）
状态：MVP 功能闭环已完成，本文档补齐产品定义层
产品代号：moba-build-agent
GitHub 仓库：`olivia-happy/moba-build-agent`（待推送）

## 1. 一句话定位

面向《王者荣耀》玩家的**本地优先、单帧触发**的动态出装决策助手：玩家在选人/商店阶段主动截取一帧，本地识别敌方阵容后，由可解释规则引擎返回带证据的出装建议与紧急秒换方案。**不替玩家操作游戏。**

## 2. 背景与问题

### 2.1 玩家侧痛点

大量玩家出装依赖两条路径，各有缺陷：

| 现有路径 | 缺陷 |
| --- | --- |
| 只跟系统推荐出装 | 不理解装备功能，逆风/被针对时不会调整 |
| 看攻略/问朋友 | 覆盖不到当前对局阵容，出装时机滞后 |

具体表现：不知道"为什么这局要先出魔抗"、不知道"对面有程咬金要早出制裁梦魇"、被刺客切时"只知道走位不知道秒换保命装"。玩家真正缺的不是"最强出装表"，而是**针对这一局敌方阵容、在当下经济约束下、可执行的决策及理由**。

### 2.2 决策链路缺失

MOBA 出装本质是一道带约束的决策题，约束是显式的：

- 敌方 5 人机制 → 优先需求（法爆/物爆/控制/回血/护盾…）
- 装备栏格子（6 格）、金币、复活甲每局限 2 次、鞋类唯一组
- 紧急场景：金身/复活甲/名刀/血魔/苍穹的秒换优先级

但游戏内没有任何入口把它结构化呈现给玩家。这是本产品切入的产品缝隙。

## 3. 目标用户与场景

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| 中低段位玩家（钻石及以下为主） | 常规出装、被针对不知如何调整 | "现在该买什么、为什么" |
| 有一定基础的玩家 | 关键团战前的装备判断 | 可解释、不黑箱的建议 |
| 保守玩家（隐私顾虑） | 不愿意安装云端分析工具 | 全程本地、不上传画面 |

不做：高端赛事职业选手的最优解研究——他们的需求是策略博弈而非装备科普，且对工具合规极敏感。

## 4. 产品目标与指标

### 4.1 当前阶段（MVP）目标

交付可复现的完整演示闭环 + 严格的产品边界，作为可公开展示的 AI 应用案例。不声称提升胜率。

### 4.2 上线后的产品指标（分层定义）

| 层 | 指标 | 说明 |
| --- | --- | --- |
| 业务层 | 建议采纳率、紧急秒换正确执行率、主动纠错率 | 玩家是否照做、识别错了能否低成本纠正 |
| 系统层 | 识别 Top-1 准确率、识别-建议全链路时延、规则可追溯率 | 本地引擎确定性 |
| 体验层 | 单次会话时长、二次使用率 | 是否真的在局内被使用 |

红线护栏：识别置信度不足必须重试/手选，绝不把低置信度输入喂给决策引擎；建议必须带证据与边界声明。

## 5. 核心流程（已实现闭环）

```text
玩家点悬浮球（Android）→ 系统截图授权 → 截取 1 帧（.lum 灰度，原始帧不上传）
  → 本地裁剪 5 个头像 → 16×16 亮度网格匹配官方头像指纹索引
  → 返回每个槽位 Top-3 候选 + 置信度
  → 玩家确认 / 点选纠正 / 手动输入英雄 ID   ← 人为确认是硬门禁
  → 调本机 FastAPI 规则引擎
  → 敌方机制标签聚合 → 优先需求排序
  → 装备功能覆盖 + 金币/格子/鞋类唯一组/复活甲次数约束
  → 返回带证据的出装建议 + 紧急秒换方案
```

关键设计：**识别结果必须人工确认后才进入决策**。这同时解决"误识别进错推荐"和"隐私红线"两个问题。

## 7. 关键产品决策：AI 边界

| 环节 | 谁负责 | 为什么 |
| --- | --- | --- |
| 英雄识别 | 本地图像指纹 + 人工确认 | 选人界面无官方结构化数据；人必须兜底防误判 |
| 威胁→需求排序 | 显式规则引擎 | 可解释、可测试，拒绝黑箱 |
| 出装建议 | 规则 + 官方装备文本证据 | 每条可追溯到装备机制 |
| 紧急秒换 | 规则引擎 + 金币/格子/次数约束 | 给可执行方案而非"注意走位" |
| 是否执行 | 玩家 | 产品不自动点击、不自动购买、不读取游戏内存 |

**合规红线（对外叙事重点）**：不读取游戏内存、不自动点击、不自动购买、不提供规避反作弊的能力、不调用官方战绩接口、不需要任何 API key、原始截图不上传只留手机本地、识别需玩家确认。产品只做"信息辅助决策"，不做"代打"。

## 8. 评测方案

- 后端：pytest 42 项（装备目录、威胁聚合、紧急秒换约束、证据格式），全部本地、确定性、零成本。
- Android：Kotlin 单元测试 13 项，APK 构建通过。
- E2E：识别 → 确认 → 决策全链路实测。
- 评测边界声明：不宣称提升胜率；demo 用官方公开静态资源 fixture，结论仅为演示质量，非真实对局 ROI。

## 9. 数据边界

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 英雄目录 + 头像 | pvp.qq.com 官方公开静态资源 | 构建可复现的指纹索引 |
| 装备目录 | pvp.qq.com item.json | 装备知识库 |
| 玩家截图 | 手机本地（用户主动授权、一帧即停） | 仅降采样为 5×16×16 灰度网格；原始帧不离开手机 |

所有数据可复现构建，带来源 URL、获取时间与内容哈希校验。

## 10. 非目标

- 不做代打/自动操作/读内存
- 不做云端分析、不上传画面
- 不调用官方或第三方战绩接口
- 不伪装成"唯一最优解"
